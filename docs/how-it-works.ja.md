# 仕組み

[English](how-it-works.md) | **日本語**

記事は Zenn で一度だけ書きます．このリポジトリは，そのうち Qiita へ展開する印を付けた記事の Qiita 版を持ち，Qiita への投稿もここから行います．

## 流れ

すべて Zenn のリポジトリの GitHub Actions ワークフローが行います．記事・画像・変換ツールに触れる `main` ブランチへの push のたびに走るほか，push が無い日でも待機が明けた記事を拾えるよう，毎日 09:13 JST にも走ります．

1. **変換する．** `zenn-tools qiita --apply` が frontmatter に `qiita: true` を持つ Zenn の記事をすべて読み，準備ができたものを `public/<Zenn の記事 ID>.md` へ変換します．
2. **記事と画像を push する．** 変換した記事と画像をこのリポジトリへ commit して push します．Qiita が記事を表示する時点で画像が配信されているよう，画像を先に公開します．
3. **投稿する．** Qiita CLI（`qiita publish --all`）が新しい記事を投稿し，内容の変わった記事を更新します．
4. **Qiita の記事 ID を記録する．** Qiita CLI は発行された記事の `id` と `updated_at` を `public/` の各ファイルへ書き込みます．ワークフローはこれをここへ commit し直します．投稿が途中で失敗してもこの手順は走ります．ID を記録しないと，次の実行で同じ記事をもう一度投稿してしまうからです．

## 変換される条件

記事が `public/` へ書かれるのは，次をすべて満たすときだけです．

- Zenn で公開済み（`published: true`）で，Zenn の公開日から設定した待機日数（既定は 3 日）が過ぎている．
- タイトルと 1〜5 個の topics を持つ．Zenn の topics が Qiita のタグになる．
- 使っている画像がすべて存在する．

タイトル・タグ・本文が変わっていない記事は書き直しません．Qiita を無駄に更新しないためです．

## 変換の内容

各記事の冒頭に，Zenn の元記事へのリンクを置きます．Zenn 独自の記法は Qiita の記法へ書き換えます．

- `:::message` は `:::note` に，`:::details` は `<details>` にする．
- ディスプレイ数式は `math` のコードブロックにする．
- 埋め込み（`@[card]`，`@[github]`，`@[youtube]` など）は URL だけの行にする．Qiita がリンクカードとして表示する．
- 画像はこのリポジトリを指すようにする（下記）．

コードブロックはそのまま残します．

## 画像

画像はこのリポジトリから `raw.githubusercontent.com` 経由で配信します．ファイル名には画像の内容から計算したハッシュが付きます（`images/<記事>/<名前>-<ハッシュ>.png` など）．画像を差し替えると URL が変わるので，キャッシュに関係なく Qiita に新しい画像が出ます．古い画像は記事の過去の版が参照しているので残します．

## このリポジトリを手で編集しない

- **`public/` の記事** は，Zenn 側が次に変わったときに上書きされます．Qiita 上で直接編集した場合も，ここの写しが Qiita の記事より古くなるため，Qiita CLI が次の更新を拒否します．
- **`public/` の `id` の行** は，各ファイルと Qiita の記事を結び付けています．これが失われると，次の実行で記事が二重に投稿されます．
- **書き込むのはワークフローだけです．** 書き込み元を 1 つにして，同時の push による記事 ID の取り違えを防いでいます．

記事を直すときは Zenn で直します．Qiita から記事を取り下げるときは，Qiita 上で自分で非公開か削除にします．Zenn で非公開にしても，`qiita: true` を外しても，Qiita の記事は消えません．
